# Демонстрация проекта: прогнозирование дефолта

Команды ниже предназначены для Windows PowerShell.

## демонстрация

- Открыть README репозитория и успешный запуск GitHub Actions.
- Подготовить ноутбук или сохранённые результаты MLflow и DVC.
- Запустить Docker Desktop и открыть PowerShell в папке полного проекта.
- Проверить, что доступны `examples/request.json` и образ `credit-default-api:local`.
- Если контейнер уже работает, использовать его; повторный запуск не требуется.

Проверка работающего контейнера:

```powershell
docker ps --filter "name=credit-default-api"
```

Если контейнер не запущен:

```powershell
docker run --rm -d --name credit-default-api -p 127.0.0.1:8000:8000 credit-default-api:local
```

Дождаться готовности приложения перед запросами. Текущий контейнер создан с `--rm`: после его остановки он удаляется, а образ сохраняется.

## 1. Задача 



Я разработала учебный сервис прогнозирования дефолта по кредитной карте. На вход он получает характеристики клиента и историю счетов, платежей и просрочек. На выходе возвращает оценку вероятности дефолта и класс при зафиксированном пороге.

Данные: Default of Credit Card Clients, 30 000 наблюдений. Целевой класс `1` - дефолт. `ID` используется для контроля данных и исключается из входов модели.

## 2. Подготовка данных и Pipeline

 `src/validation/validate_data.py`, `src/features/build_features.py` и `src/models/pipeline.py`.

 Сначала проверяются структура, типы и допустимые значения исходных данных. Great Expectations выполняет 72 проверки. Затем Pipeline создаёт признаки, заполняет пропуски, масштабирует числовые признаки и кодирует категории. Все преобразования сохраняются вместе с моделью.

Шесть дополнительных признаков: число месяцев с просрочкой, максимальная просрочка, средний счёт, средний платёж, отношение последнего счёта к лимиту и возрастная группа.

Из 23 исходных признаков получается 29 до кодирования категорий.

## 3. Эксперименты и качество 

Показать сохранённые эксперименты MLflow из ноутбука или ранее сделанные скриншоты. Исходные шесть запусков находятся в `experiments/mlflow_checkpoint.zip` полной резервной копии; новые запуски воспроизведения записываются отдельно.

В MLflow сохранены базовый запуск и пять вариантов логистической регрессии с разными значениями C. Параметры и порог выбраны на обучающей части с использованием кросс-валидации. После выбора они зафиксированы, и модель оценена на отложенной тестовой выборке.

Итоговые параметры: `C=0.1`, порог `0.3`. Обучение: 24 000 строк, тест: 6 000 строк; стратифицированное разбиение, `random_state=42`.

| Метрика теста | Значение |
| --- | ---: |
| ROC-AUC | 0.7613 |
| Precision | 0.5392 |
| Recall | 0.5026 |
| F1 | 0.5203 |

> ROC-AUC характеризует способность модели ранжировать клиентов по риску. При пороге 0.3 модель обнаружила около половины случаев дефолта в тесте. Порог определяет баланс между пропущенными дефолтами и ложными срабатываниями.

Не подбирать новые параметры по результатам отложенного теста.

## 4. Воспроизводимость и CI 

 `dvc.yaml`, `dvc.lock`, `params.json`, затем успешный GitHub Actions.

> DVC описывает этапы подготовки и обучения, их зависимости, параметры и результаты. Git хранит код и DVC-метаданные. Полная резервная копия содержит данные, модели и эксперименты. При повторном выполнении с зафиксированными параметрами были получены те же тестовые метрики.

Для демонстрации результатов DVC использовать уже проверенный вывод в ноутбуке: `dvc status`, `dvc metrics show` и пропуск актуальных этапов при `dvc repro`. Запускать эти команды вживую можно в подготовленной среде с DVC и доступом к данным.

В образ API установлены зависимости для обслуживания запросов. Для работы с DVC нужна отдельная среда разработки.

> При изменении кода GitHub Actions устанавливает зависимости, проверяет оформление Black, запускает Flake8 и pytest. После добавления мониторинга подтверждены 30 успешных тестов.

[Успешный запуск CI](https://github.com/Amalficode/credit-default-mlops/actions/runs/42105354563).

## 5. API в Docker 

Docker Desktop → Containers → `credit-default-api`.

> Docker-образ содержит Python, библиотеки, код сервиса и сохранённую модель. На Windows проверила сборку образа, запуск контейнера и совпадение прогноза с результатом в Colab.

### Состояние сервиса

```powershell
Invoke-RestMethod http://127.0.0.1:8000/health | ConvertTo-Json
```

Ожидаемый ответ:

```json
{"status":"ok","model_loaded":true}
```

### Прогноз на сохранённом примере

```powershell
$body = Get-Content .\examples\request.json -Raw
Invoke-RestMethod -Uri http://127.0.0.1:8000/predict -Method Post -ContentType "application/json" -Body $body | ConvertTo-Json
```

Ожидаемый ответ; незначительные различия в последних знаках допустимы:

```json
{
  "default_probability": 0.7033040958180882,
  "prediction": 1,
  "threshold": 0.3
}
```

> Модель оценила вероятность дефолта для этого примера примерно в 70.33%. Поскольку оценка выше зафиксированного порога 30%, возвращён класс 1.

### Некорректный платёж

```powershell
$invalid = $body | ConvertFrom-Json
$invalid.PAY_AMT1 = -100
try {
    Invoke-RestMethod -Uri http://127.0.0.1:8000/predict -Method Post -ContentType "application/json" -Body ($invalid | ConvertTo-Json)
} catch {
    if ($null -eq $_.Exception.Response) { throw }
    Write-Host "HTTP:" ([int]$_.Exception.Response.StatusCode)
}
```

Ожидаемый результат: `HTTP: 422`.

> Сервис проверяет входные данные и отклоняет запрос с отрицательной суммой платежа.

При необходимости открыть [Swagger UI](http://127.0.0.1:8000/docs). Он доступен, пока контейнер работает.

## 6. Мониторинг PSI

При работающем API выполнить из полной папки проекта:

```powershell
$projectDir = (Get-Location).Path
docker run --rm --network container:credit-default-api --mount "type=bind,source=$projectDir,target=/workspace" --workdir /workspace credit-default-api:local python -m src.monitoring.monitor
```

Скрипт отправляет в API 200 строк отложенного теста, проверяет совпадение
ответов с сохранённой моделью и рассчитывает PSI относительно обучающих оценок.
Показать вывод и `reports/drift_report.json`. В проверенном локальном запуске:
24 000 эталонных строк, 200 ответов API из 200, PSI = 0.039658 (шесть знаков),
условный уровень сдвига — низкий. Прогнозы API совпали с сохранённой моделью.
Это учебная имитация новых данных; PSI характеризует
распределение оценок, а не качество классификации.
[Подробнее о мониторинге](monitoring.md).

## 7. Завершение
